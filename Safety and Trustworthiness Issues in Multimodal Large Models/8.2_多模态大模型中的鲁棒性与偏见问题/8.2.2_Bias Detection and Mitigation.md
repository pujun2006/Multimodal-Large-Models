Bias Detection and Mitigation.py代码实现了一个**基于 BERT 的文本分类流程**，并在其中加入了 **FGM（Fast Gradient Method，快速梯度法）词嵌入级对抗训练**，最后通过反事实句对（Counterfactual Pairs）来观察模型在替换性别代词时的预测概率差异。

下面按模块逐层拆解说明，并指出它在工程与偏见研究中的作用及局限。

---

### 一、 整体架构与执行流程

整个脚本分为 5 个部分：

1. **设备与数据集封装（`device`、`TextDataset`）**：自动选择 GPU 或 CPU，将文本编码为固定长度的 `input_ids` 和 `attention_mask`。
2. **反事实解耦样本构造（`texts`、`labels`）**：将同一职业的 `"She ..."` 与 `"He ..."` 赋予相同标签，避免模型把性别词直接当成目标标签。
3. **模型与优化器初始化**：加载 `bert-base-uncased` 二分类模型与 `AdamW` 优化器。
4. **FGM 对抗训练（`train_with_fgm`）**：在词嵌入（Embedding）空间计算梯度并施加归一化扰动，联合优化原始损失与对抗损失。
5. **反事实概率对比评估（`evaluate_counterfactual_pairs`）**：输入成对句子，计算类别 `1` 的预测概率及其绝对差值。

---

### 二、 核心模块详解

#### 1. 设备选择与 `TextDataset`

* `device = torch.device("cuda" if torch.cuda.is_available() else "cpu")` 让代码可在无显卡环境下运行。
* `TextDataset` 继承 `torch.utils.data.Dataset`：
* `tokenizer(..., max_length=32, padding="max_length", truncation=True, return_tensors="pt")` 返回形状为 `(1, 32)` 的张量。
* `.squeeze(0)` 将其降维为 `(32,)`，方便 `DataLoader` 按 `batch_size=2` 拼接成 `(2, 32)`。
* `label` 转为 `torch.long`，满足交叉熵损失函数对类别索引的类型要求。



#### 2. 样本标签与敏感词解耦

* 原始示例将 `"She ..."` 和 `"He ..."` 成对放入 `texts`，并给同一职业分配相同 `labels`（如 `doctor` 与 `engineer` 为 `1`，`nurse` 与 `teacher` 为 `0`）。
* 这样做的目的是**打破“代词 = 类别”的虚假捷径**，使训练信号集中在职业/语义本身，而不是代词表面特征。

#### 3. FGM 对抗训练（`train_with_fgm`）

文本输入是离散 token ID，无法直接求连续梯度，因此 FGM 作用于词向量层：

1. **获取可求导词向量**：
`inputs_embeds = embedding_layer(input_ids).detach()`
`inputs_embeds.requires_grad_(True)`
先断开与计算图的历史连接，再显式开启梯度追踪，确保只针对当前词嵌入求梯度。
2. **第一次前向与反向传播**：
将 `inputs_embeds` 传给 `model(inputs_embeds=..., attention_mask=..., labels=...)` 得到 `loss`，调用 `loss.backward()` 计算 `inputs_embeds.grad`。
3. **计算归一化扰动（FGM 核心公式）**：

$$\text{perturbation} = \epsilon \cdot \frac{\nabla_{e} L}{\Vert{}\nabla_{e} L\Vert{}_2 + \text{eps}}$$



代码中 `torch.norm(grad, dim=-1, keepdim=True) + 1e-8` 按每个 token 的向量维度求 L2 范数并防止除零，再乘以扰动幅度 `epsilon`（调用时传入 `0.5`）。
4. **对抗样本前向与梯度累加**：
`perturbed_embeds = (inputs_embeds + perturbation).detach()` 生成扰动后的词向量，再次前向传播得到 `adv_loss` 并执行 `adv_loss.backward()`。
由于 `optimizer.zero_grad()` 只在每个 batch 开始时调用一次，两次 `backward()` 的梯度会累加到模型参数上（`total_loss` 仅用于打印日志均值）。

#### 4. 反事实评估（`evaluate_counterfactual_pairs`）

* `model.eval()` 关闭 Dropout 等训练层，配合 `torch.no_grad()` 节省显存并加速推理。
* 对每一对 `(female_text, male_text)`，分别计算 `softmax` 后类别 `1` 的概率 `p1`，并输出 `abs(probs[0] - probs[1])`。
* **差异越小**，说明模型在仅替换主语代词时，对类别 `1` 的输出概率越一致。

### 四、 关键细节与局限性

* **仅 8 条训练样本与 2 个 Epoch**：数据集极小且缺乏独立验证/测试集，模型容易过拟合词面或句式模板，评估结果只能说明机制走通，不能代表真实泛化能力。
* **FGM 提升鲁棒性不等于彻底消除偏见**：FGM 本质是提升模型对嵌入空间局部扰动的平滑性与鲁棒性；若预训练语料或下游任务本身存在系统性刻板印象，仅靠少量样本上的 FGM 难以完全消除偏见，通常还需结合更丰富的反事实增强数据、群组公平性约束或去偏微调策略。
* **评估句式较单一**：`test_pairs` 仅测试了 `"She/He is a doctor."` 与 `"She/He is a nurse."`，且未将 `"doctor"`、`"nurse"` 等词本身纳入反事实对比，评估维度较为基础。
