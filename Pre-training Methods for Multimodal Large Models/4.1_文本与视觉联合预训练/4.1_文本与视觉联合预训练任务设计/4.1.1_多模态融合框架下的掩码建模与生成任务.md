在多模态融合框架下，**掩码建模（Masked Modeling）**与**生成任务（Generation）**构成了从“双向表征理解”向“条件与自回归生成”演进的核心主线。两者分别侧重于**上下文/跨模态补全**与**序列/目标空间建模**，在早期编码器-融合器架构（如 ViLBERT、LXMERT、BLIP 等）和现代多模态大模型（MLLM）中有着不同的形式化与工程实现。

## 一、 多模态融合框架下的掩码建模

多模态掩码建模的核心思路是：**主动遮蔽部分输入模态的信息，迫使融合模块利用另一模态及未遮蔽上下文进行推理补全**。根据被遮蔽模态与融合结构的不同，主要分为以下三类：

### 1. 多模态掩码语言建模（Multimodal MLM）

* **任务机制**：对输入文本序列按一定比例（如常见 15%）随机替换为 `[MASK]` 或干扰词元，融合编码器通过自注意力或交叉注意力同时 attend 到**未遮蔽文本词元**与**图像区域/Patch 特征**，预测原始词元分布。
* **融合与训练要点**：
* **避免“纯文本捷径”**：若句子本身语法与语义已高度确定，模型可能不看图像也能猜出词元。因此常在“图像-文本对”上施加 MLM，使缺失的视觉属性（如颜色、数量、空间方位、OCR 词元）必须通过跨模态注意力读取。
* **注意力掩码设计**：在融合编码器或统一 Transformer 中，常对文本侧采用双向注意力（Bidirectional Attention）以充分利用左右上下文，而对视觉侧提供完整或分块特征。



### 2. 掩码图像建模 / 掩码视觉建模（MIM / MVM）

* **任务机制**：随机遮蔽图像网格中的一部分 Patch（例如高遮蔽率设计，如 40%～75% 视具体方法而定），让视觉骨干或跨模态融合网络预测被遮蔽 Patch 对应的目标表征。
* **重建目标类型**：
* **离散 Token 索引**：借助视觉分词器（如 VQ-VAE / 语义 Tokenizer）将图像映射为离散码本 ID，转化为类似 MLM 的分类预测。
* **连续特征或归一化像素**：预测教师网络（如 CLIP / 自监督 ViT）的隐层特征，或重建归一化后的像素值。


* **跨模态融合意义**：当 MIM 与文本条件结合时，文本描述可以提供全局语义先验，帮助模型补全局部遮蔽区域；而在纯视觉或两阶段训练中，MIM 更偏向增强细粒度空间与局部纹理表征。

### 3. 联合/交错掩码建模（Joint / Interleaved Masked Modeling）

* **任务机制**：在同一序列或统一编码器中同时对文本词元和视觉 Patch/Token 进行掩码预测，甚至在图文交错序列中随机遮蔽部分文本片段与图像块。
* **优势与难点**：
* **优势**：统一了图文双通道的双向表征学习，适合检索、VQA、图文匹配等多理解任务联合训练。
* **难点**：文本与视觉的**信息密度与冗余度差异极大**（图像空间相关性强、局部冗余高，文本词元信息密度高），若掩码比例、损失权重或注意力可见性未对齐，容易出现某一模态收敛过快或梯度失衡。

## 二、 多模态融合框架下的生成任务

与掩码建模侧重“双向填空/补全”不同，生成任务通常依赖**因果注意力掩码（Causal Attention Mask）**或**条件生成机制**，按序列顺序或目标空间逐步产出输出。

### 1. 视觉条件自回归文本生成（Vision-Conditioned Autoregressive LM / Captioning）

* **任务机制**：将视觉特征作为条件上下文输入语言模型，按自回归方式逐词预测文本序列：

* **主流融合接口**：
* **投影映射（Linear / MLP Projector + Token 拼接）**：将视觉编码器输出的 Patch 特征通过 MLP 或重采样器（如 Q-Former / Perceiver Resampler）映射到 LLM 词嵌入空间，直接拼接在文本前缀位置，随后由 LLM 执行因果自回归解码。
* **交叉注意力注入（Cross-Attention）**：在 LLM 层间插入交叉注意力层，Query 来自语言序列，Key/Value 来自视觉特征，在保持语言主干参数稳定的同时引入视觉信息。



### 2. 交错图文自回归生成（Interleaved Multimodal Autoregressive Modeling）

* **任务机制**：将多张图像与多段文本按自然顺序排成统一序列（如文档、网页、多图推理链），在统一序列上执行 Next-Token Prediction，使视觉 Token 与文本 Token 共同参与因果注意力计算。
* **核心价值**：
* 支持**多图对比与时序/空间推理**；
* 支持 **Few-shot / In-Context Learning**（通过提供若干图文示例引导输出格式或推理路径）；
* 更贴近真实长上下文与复杂文档理解场景。



### 3. 统一与跨模态视觉生成（Discrete Token / Diffusion / Flow Matching）

当融合框架不仅“看懂并说”，还要“生成图像或跨模态输出”时，主要有两类路线：

* **离散视觉 Token 自回归**：通过图像 Tokenizer 将图像转为离散 Token 序列，与文本词表合并后统一做自回归预测。优点是架构与 LLM 高度统一，缺点是 Token 数量多、推理步数长且局部细节受限于码本量化误差。
* **多模态隐状态驱动扩散 / 流匹配（Diffusion / Flow Matching）**：语言或融合模型输出语义条件向量/隐状态，由扩散或流匹配生成器迭代去噪生成高保真图像。优点是画质与细节表现强，缺点是跨组件对齐与端到端联合训练复杂度较高。

## 三、 掩码建模与生成任务的对比及融合演进

| 维度 | 掩码建模（MLM / MIM） | 自回归 / 条件生成（LM / 交错 / 视觉生成） |
| --- | --- | --- |
| **注意力机制** | 多为**双向注意力**（利用前后文与视觉上下文） | 文本/序列侧多为**因果注意力**（仅依赖历史状态） |
| **预测目标** | 被遮蔽词元或视觉块/特征 | 下一个词元/视觉 Token 或目标分布 |
| **优势能力** | 双向上下文理解、细粒度特征补全、判别与检索适配 | 开放式描述、VQA 回答、指令遵循、多轮对话与生成 |
| **主要短板** | 与开放式长序列生成的训练-推理目标存在差异 | 长视觉序列计算开销大，易受曝光偏差与幻觉影响 |

### 框架演进与工程实践建议

1. **从“多头判别+掩码”向“统一生成接口”收敛**：早期融合架构常将 ITC、ITM、MLM 并行叠加；现代 MLLM 更倾向于将视觉信息对齐进 LLM 语义空间，以统一的语言/多模态生成目标承载 Caption、VQA、OCR、定位与指令遵循。
2. **用高质量合成数据与结构化目标弥补生成短板**：纯网页图文对的描述往往简略或含噪，引入细粒度描述、OCR 文本、坐标/定位标注与多轮指令数据，能显著提升生成任务的忠实度，降低视觉幻觉。
3. **关注视觉 Token 长度与分辨率权衡**：高分辨率与多图输入会急剧拉长序列长度，在融合前采用空间合并/重采样（Token Compression）或动态分辨率分块，是兼顾细粒度感知与推理吞吐的关键。
