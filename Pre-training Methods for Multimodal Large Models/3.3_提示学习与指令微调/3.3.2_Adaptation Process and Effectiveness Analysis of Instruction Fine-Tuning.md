Adaptation Process and Effectiveness Analysis of Instruction Fine-Tuning.py代码实现了一套**针对显存受限环境（如单卡约 14.5 GiB）优化的因果语言模型（Causal LM）指令微调与微调前后对比实验流水线**。它围绕“防 OOM、准 Loss 掩码、清对照评估”做了完整工程封装，下面按模块详细说明。

---

### 一、 显存管理与环境初始化

```python
import os
os.environ.setdefault("PYTORCH_CUDA_ALLOC_CONF", "expandable_segments:True")

```

* **`PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`**：在导入 `torch` 之前配置 CUDA 内存分配器，支持可扩展内存段，减少反复申请/释放不同长度张量时的显存碎片。
* **`clean_gpu_memory()`**：在 `main()` 开头主动清理全局作用域中可能残留的旧张量、模型与优化器引用，触发垃圾回收（`gc.collect()`），并清空 PyTorch CUDA 缓存与峰值显存统计（`torch.cuda.reset_peak_memory_stats()`），避免 Notebook 多次试错时旧显存叠加导致 OOM。
* **`set_seed(42)`**：固定 Python `random` 与 PyTorch CPU/GPU 随机种子，保证数据打乱、初始化与训练过程尽量可复现。

### 二、 因果语言模型数据集与动态 Padding

#### 1. `CausalInstructionDataset`：Prompt 拼接与 `-100` 掩码

对于 Decoder-only 架构（如 `Qwen/Qwen2.5-0.5B-Instruct`），监督微调通常把 `prompt + target` 拼成同一条序列训练自回归预测：

* **序列拼接**：将 `"指令：...\n回答："` 的 token IDs 与 `target` 的 token IDs 拼接，并在末尾补齐 `eos_token_id`（若尚未以它结尾），最后截断到 `max_length`。
* **Loss 掩码（`-100`）**：
* `labels[:prompt_len] = -100`：让交叉熵损失忽略输入指令与引导前缀，**只监督模型学习生成 `target` 部分**。
* 后续在 `collate_fn` 中对补齐的 padding 位置同样设为 `-100`，确保填充 token 不参与损失计算。



#### 2. `make_collate_fn`：按 Batch 动态对齐长度

* 不同于预先把每条样本统一补到 `max_length=256`，`collate_fn` 会在每个 batch 内计算**当前批次样本的最大长度 `max_len**`，只把该 batch 内的短序列补齐到 `max_len`（`input_ids` 补 `pad_token_id`，`attention_mask` 补 `0`，`labels` 补 `-100`）。
* 在短文本微调中，这能显著减少无效计算与激活值显存占用。

### 三、 局部解冻策略：`freeze_except_top_layers`

```python
def freeze_except_top_layers(model, num_top_layers: int = 2) -> None:

```

在不依赖 `peft` 的情况下，通过控制 `param.requires_grad` 实现**参数子集微调**：

1. 先将模型所有参数的 `requires_grad` 设为 `False`（冻结底座大部分权重）。
2. 解冻最后 `num_top_layers` 个 Transformer 层（`model.model.layers[-num_top_layers:]`）以及输出投影头（`lm_head`），让它们参与梯度计算与参数更新。
3. 统计并打印可训练参数量占比，随后优化器 `AdamW` 仅接收 `[p for p in model.parameters() if p.requires_grad]`，从而大幅降低梯度与优化器动量状态占用的显存。

### 四、 评估、推理生成与主训练循环

#### 1. `evaluate_loss` 与 `generate_predictions`

* **`evaluate_loss`**：在 `model.eval()` 与 `torch.no_grad()` 下计算验证集平均损失，用于观察泛化趋势是否随训练出现过拟合。
* **`generate_predictions`**：用相同的 `f"指令：{inst}\n回答："` 前缀编码输入，调用 `model.generate(..., max_new_tokens=80, do_sample=False)` 做确定性贪心解码，并通过 `output_ids[0][input_len:]` **只截取新生成的回复 token** 再解码，避免把输入提示词一起打印出来。

#### 2. `main()` 执行流程

1. **选择半精度底座**：优先使用 `torch.bfloat16`（若硬件支持），否则回退到 `torch.float16`，降低模型权重与前向激活显存。
2. **微调前基线记录**：训练前先算 `initial_val_loss` 与 `before_preds`，建立对照基准。
3. **多轮训练与监控**：按 `epochs` 遍历 `train_loader`，执行 `zero_grad → forward → loss.backward() → optimizer.step()`，每轮结束后打印 `Train Loss` 与 `Val Loss`，并在训练后输出峰值显存（`peak_gib`）。
4. **微调前后逐条对比**：打印每条验证指令的参考答案、微调前输出与微调后输出，直观检验指令遵循与回答变化。
