Design and Optimization of Parameter Sharing Framework.py代码实现了一个**基于共享多头自注意力层的硬参数共享多模态多任务分类原型**（图像 10 分类 + 文本 2 分类）。它的核心设计思路是：**先将不同维度的图像与文本输入各自线性投影到同一隐空间并堆叠成长度为 2 的序列，再让二者共用同一个 `SharedAttention` 模块做自注意力交互、残差连接与 `LayerNorm`，最后按位置索引拆回并送入各自的任务头完成预测**。

下面从**整体数据流转与张量形状变化**、**核心类逐一拆解**、**训练与评估流程**以及**工程细节与可改进点**四个部分详细说明：

---

### 一、 整体数据流转与张量形状变化

假设 `batch_size = 16`、`img_input_dim = 256`、`text_input_dim = 128`、`hidden_dim = 64`、`img_output_dim = 10`、`text_output_dim = 2`：

1. **单模态维度对齐**：
* `img_input`（`[16, 256]`）经 `self.img_encoder` 映射为 `img_features`（`[16, 64]`）。
* `text_input`（`[16, 128]`）经 `self.text_encoder` 映射为 `text_features`（`[16, 64]`）。


2. **序列堆叠（构造双 Token 序列）**：
* `torch.stack((img_features, text_features), dim=1)` 在第 1 维新增序列长度维度，得到 `combined_features`（`[16, 2, 64]`），其中索引 `0` 对应图像 token，索引 `1` 对应文本 token。


3. **共享注意力交互与归一化**：
* `self.shared_attention(combined_features)` 对这两个 token 执行多头自注意力计算、残差相加与 `LayerNorm`，再经过 `ReLU`，输出 `shared_features`（`[16, 2, 64]`）。


4. **索引解包与多任务预测**：
* 取出 `shared_features[:, 0, :]`（`[16, 64]`）送入 `self.img_task_head`，输出 `img_output`（`[16, 10]`）。
* 取出 `shared_features[:, 1, :]`（`[16, 64]`）送入 `self.text_task_head`，输出 `text_output`（`[16, 2]`）。



---

### 二、 核心模块逐一解析

#### 1. `SharedAttention`（共享多头自注意力层）

* **`nn.MultiheadAttention(embed_dim=hidden_dim, num_heads=num_heads, batch_first=True)`**：
* 显式指定 `batch_first=True`，使输入输出形状为 `(batch_size, seq_len, embed_dim)`，与当前 `[B, 2, 64]` 保持一致。
* 在 `forward(self, x)` 中调用 `self.attention(x, x, x)`，即以同一个序列 `x` 同时作为 Query、Key 和 Value 做自注意力，让图像 token 与文本 token 在各注意力头中彼此关注并聚合信息。


* **残差连接与 `LayerNorm**`：
* `out = self.norm(x + attn_output)` 采用典型的 **Post-LN** 残差结构，对每个样本每个 token 在 `hidden_dim` 维度上做归一化，随后通过 `self.relu(out)` 引入非线性激活。



#### 2. `TaskHead`（任务专属分类头）

* 封装单层 `nn.Linear(hidden_dim, output_dim)`，接收对应 token 的 `64` 维表征后分别映射到 `10` 维（图像分类 logits）与 `2` 维（文本分类 logits）。

#### 3. `SharedParameterModel`（多任务共享参数模型）

* 将独立投影层（`img_encoder`、`text_encoder`）、共享交互层（`shared_attention`）与独立输出头（`img_task_head`、`text_task_head`）串接在一起。
* 因为 `img_encoder` 与 `text_encoder` 参数相互独立，它们各自承担输入维度对齐与初步特征映射；而 `shared_attention` 被两个任务共同依赖，属于**部分硬参数共享**结构。

---

### 三、 训练循环与模型评估解析

* **多任务联合损失与优化**：
* 分别使用 `img_criterion = nn.CrossEntropyLoss()` 与 `text_criterion = nn.CrossEntropyLoss()` 计算两个任务的分类损失。
* 每步通过 `total_loss = img_loss + text_loss` 直接相加（相当于等权重 `1.0:1.0`），调用 `total_loss.backward()` 将两个任务的梯度同时反传至 `shared_attention` 及各自编码器，再由 `optimizer.step()`（`Adam`, `lr=1e-4`）更新参数。


* **随机数据与评估阶段**：
* 训练与测试使用的 `img_data`、`text_data`、`img_labels`、`text_labels` 均为随机张量，目的是验证维度拼接、注意力前向、多任务损失反传与推理输出链路是否正常。
* 评估时通过 `model.eval()` 与 `torch.no_grad()` 关闭梯度记录，并用 `torch.argmax(..., dim=1)` 得到最终预测类别索引。

### 五、 工程细节与可改进方向

1. **序列位置区分（Modality / Position Embedding）**：当前序列长度为 `2`，全靠索引 `0` 和 `1` 区分图像与文本；若后续扩展为多 token 序列（如多个视觉 patch + 多个文本 token），通常需要显式加入模态嵌入或位置编码，帮助注意力层区分来源。
2. **多任务损失权重与梯度平衡**：当图像 10 分类与文本 2 分类的损失量纲、收敛速度或梯度方向存在差异时，简单相加（`img_loss + text_loss`）可能使某一任务主导共享层更新，实际训练中常引入任务权重系数、不确定性加权或梯度协调策略。
3. **术语与任务语义匹配**：代码中 `self.attention(x, x, x)` 属于自注意力而非交叉注意力；同时，若两个任务本身各自独立，共享注意力会引入跨模态信息交互，在真实数据集上需对比“带共享注意力”与“单模态独立预测”的指标，确认跨模态交互确实带来正迁移而非干扰。
