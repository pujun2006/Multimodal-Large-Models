Feature-level fusion.py代码实现了一个**基于特征拼接（Feature Concatenation）的多模态特征级融合二分类原型**（以情感分类为例：`0` 为负面，`1` 为正面）。它的核心做法是：先让文本特征和图像特征各自经过独立线性编码与激活映射，再在特征维度上拼接并送入融合层与分类头完成预测。

下面从**整体工作流**、**核心类逐一拆解**、**训练与评估流程**以及**工程细节与改进方向**四个部分详细说明：

---

### 一、 整体工作流概览

1. **单模态特征映射**：输入的文本向量（`[B, 128]`）和图像特征向量（`[B, 256]`）分别经由独立的全连接层映射到相同的隐藏维度 `hidden_dim`（`64`），再通过 `ReLU` 非线性激活与 `Dropout` 正则化。
2. **特征级拼接**：将两路编码得到的 `[B, 64]` 特征沿特征维（`dim=1`）拼接，形成 `[B, 128]` 的联合特征向量。
3. **跨模态融合与分类**：拼接后的向量经 `fusion_layer`（`128 -> 64`）做跨模态特征混合，再过 `ReLU`、`Dropout` 与 `classifier`（`64 -> 2`），输出未归一化的分类 `logits`（`[B, 2]`）。
4. **训练与推理**：使用 `CrossEntropyLoss` 与 `Adam` 优化器训练 5 个 Epoch，随后在 `model.eval()` 与 `torch.no_grad()` 下对测试输入执行前向推理并取 `argmax` 得到预测类别。

---

### 二、 核心模块逐一解析

#### 1. `FeatureFusionModel.__init__`

* **单模态编码器**：
* `self.text_encoder = nn.Linear(text_input_dim, hidden_dim)`：将 128 维文本输入映射为 64 维特征。
* `self.image_encoder = nn.Linear(image_input_dim, hidden_dim)`：将 256 维图像输入映射为 64 维特征。
* 统一到 `hidden_dim` 有助于让两模态在拼接前处于同一特征尺度与维度空间。


* **融合层与分类头**：
* `self.fusion_layer = nn.Linear(hidden_dim * 2, hidden_dim)`：接收拼接后的 `64 * 2 = 128` 维特征，将其压缩并混合为 `64` 维多模态融合表征。
* `self.classifier = nn.Linear(hidden_dim, output_dim)`：将 `64` 维融合特征映射到 `output_dim=2` 个类别得分。


* **激活函数与正则化**：
* `self.relu = nn.ReLU()` 与 `self.dropout = nn.Dropout(dropout_rate)`（默认 `0.2`）。
* *注*：当前代码中 `self.relu` 与 `self.dropout` 都在 `forward` 中复用同一实例，对 `nn.ReLU` 和无状态的 `nn.Dropout` 来说在功能上可行，但实际工程中若希望明确区分不同层或分别调整丢弃率，拆分为独立模块会更清晰。



#### 2. `FeatureFusionModel.forward`

* **阶段一（独立编码）**：
```python
text_features = self.dropout(self.relu(self.text_encoder(text_input)))
image_features = self.dropout(self.relu(self.image_encoder(image_input)))

```


两路分别完成线性变换 → `ReLU` → `Dropout`，各自输出形状为 `[batch_size, hidden_dim]`。
* **阶段二（特征拼接）**：
```python
fused_features = torch.cat((text_features, image_features), dim=1)

```


按 `dim=1` 拼接，形状变为 `[batch_size, hidden_dim * 2]`。
* **阶段三（融合与分类输出）**：
```python
fused_output = self.dropout(self.relu(self.fusion_layer(fused_features)))
logits = self.classifier(fused_output)

```


输出 `logits` 形状为 `[batch_size, output_dim]`，直接适配 `nn.CrossEntropyLoss()`（内部自带 `LogSoftmax` + `NLLLoss`）。

### 三、 超参数、模拟数据与训练/评估流程

* **配置与设备**：`batch_size = 16`、`text_input_dim = 128`、`image_input_dim = 256`、`hidden_dim = 64`、`output_dim = 2`、`lr = 1e-4`，自动检测 `cuda` 或使用 `cpu`。
* **随机模拟数据**：
* `text_data`、`image_data` 为高斯随机张量，`labels` 为 `0` 或 `1` 的随机整数标签。
* 这组数据用于**验证模型前向形状、损失计算、反向传播与推理链路是否畅通**；由于输入与标签之间没有真实语义关联，实际任务中需替换为真实提取的文本/图像特征与标注标签。


* **训练循环与推理评估**：
* `model.train()` 开启 `Dropout`；每次迭代执行 `optimizer.zero_grad()` → 前向计算 → `loss.backward()` → `optimizer.step()`，并打印当前 Epoch 的 Loss。
* 评估阶段切换到 `model.eval()`（关闭 `Dropout`），使用 `with torch.no_grad():` 禁用梯度记录以降低显存开销与加速计算，随后用 `torch.argmax(test_outputs, dim=1)` 输出预测类别索引。

### 五、 实际工程中的常见改进方向

1. **接入真实预训练特征或序列表征**：示例中的 `text_input` 与 `image_input` 是一维向量，真实场景中可来自文本/视觉编码器的池化特征；若输入是序列特征（如 `[B, Seq, Dim]`），则更适合结合注意力机制或序列聚合后再融合。
2. **模态平衡与缺失鲁棒性**：当某一模态特征噪声较大或缺失时，简单拼接可能受干扰，可进一步引入门控/加权融合、特征归一化（如 `LayerNorm`）或在训练中加入模态丢弃/掩码增强。
3. **数据集划分与指标评估**：真实训练需划分独立的训练集、验证集与测试集，并在验证集上监控准确率（Accuracy）、精确率/召回率/F1 等指标，同时注意排查是否存在“只靠单模态即可猜中”的模态捷径问题。
