Data-level fusion.py这段代码实现了一个**基于 RGB 图像与深度图（Depth）的数据级融合（Early Fusion）分类原型**。它的核心设计思路是：**在进入特征提取网络的第一层之前，直接将空间对齐的异构通道拼接为一个统一输入张量，由同一个卷积骨干网络完成联合特征抽取与分类**。

下面从**整体架构与数据流转**、**核心类逐一拆解**、**训练与评估流程**以及**工程细节与注意事项**四个部分详细说明：

---

### 一、 整体架构与数据流转

整个前向计算不走“双分支各自抽特征再合并”的路线，而是直接走早期融合流水线：

1. **模态掩码调节（可选）**：若传入 `rgb_mask` 或 `depth_mask`，按样本粒度（`[B, 1, 1, 1]`）对对应模态做逐元素乘法，模拟模态缺失或通道屏蔽。
2. **输入层通道拼接**：将 `rgb`（`[B, 3, H, W]`）与 `depth`（`[B, 1, H, W]`）沿通道维度（`dim=1`）合并为 `[B, 4, H, W]`。
3. **统一特征提取（`self.stem`）**：第一层 `Conv2d` 直接以 `in_channels=4` 接收联合输入，在空间下采样的同时跨通道提取外观与深度关联特征，经全局平均池化与展平后输出 `[B, 64]` 向量。
4. **分类头输出（`self.classifier`）**：经过全连接层、`ReLU`、`Dropout` 与最终线性映射，输出形状为 `[B, num_classes]` 的分类 `logits`。

---

### 二、 核心模块逐一解析

#### 1. `DataLevelFusionModel.__init__`

* **特征提取主干（`self.stem`）**：
* 首层 `Conv2d(in_channels=4, out_channels=32, kernel_size=3, stride=2, padding=1)`：将 4 通道输入映射为 32 通道，同时 `stride=2` 使空间尺寸减半（`128×128 -> 64×64`）。
* 次层 `Conv2d(in_channels=32, out_channels=64, kernel_size=3, stride=2, padding=1)`：进一步将通道扩至 64，空间尺寸再次减半（`64×64 -> 32×32`）。
* 两层卷积均搭配 `BatchNorm2d` 与 `ReLU(inplace=True)`，稳定梯度分布并引入非线性。
* `AdaptiveAvgPool2d((1, 1))` 与 `nn.Flatten()`：将任意空间分辨率特征图池化为 `[B, 64, 1, 1]` 并展平为 `[B, 64]`，使模型对输入高宽具备一定弹性。


* **分类器（`self.classifier`）**：
* `Linear(64, hidden_dim)` → `ReLU` → `Dropout(dropout_rate)` → `Linear(hidden_dim, num_classes)`，默认 `hidden_dim=128`、`num_classes=2`、`dropout_rate=0.2`。



#### 2. `DataLevelFusionModel.forward`

* **类型注解与可选掩码**：
* `rgb_mask` 与 `depth_mask` 声明为 `torch.Tensor | None = None`（Python 3.10+ 联合类型语法）。
* 当某样本对应掩码为 `0` 时，该模态整张图被置零，迫使网络在部分模态退化或缺失时仍能利用剩余模态做预测。


* **通道级拼接**：
```python
fused_input = torch.cat([rgb, depth], dim=1)

```


这是数据级融合的关键所在：外观颜色通道与深度通道在最底层即被同一个卷积核联合扫描。

### 三、 `main()` 训练与推理流程解析

1. **随机种子与设备选择**：
* `torch.manual_seed(42)` 固定随机初始化与数据生成过程，便于复现；根据 `torch.cuda.is_available()` 自动选择 `cuda` 或 `cpu`。


2. **模拟输入与掩码构造**：
* 生成 `batch_size=16`、尺寸 `128×128` 的随机 `rgb_data`（3 通道）、`depth_data`（1 通道）及随机二分类 `labels`。
* 构造 `depth_mask = (torch.rand(batch_size, 1, 1, 1, device=device) > 0.2).float()`，约 `20%` 的样本深度通道会被随机置零。


3. **训练循环（5 个 Epoch）**：
* 调用 `model.train()` 启用 `BatchNorm2d` 的批统计更新与 `Dropout`。
* 每步执行 `optimizer.zero_grad()` → 前向计算 → `criterion(outputs, labels)`（`CrossEntropyLoss`） → `loss.backward()` → `optimizer.step()`，并打印每个 Epoch 的损失值。


4. **评估/推理阶段**：
* 调用 `model.eval()` 切换 `BatchNorm2d` 与 `Dropout` 到推理模式。
* 在 `with torch.no_grad():` 上下文中关闭梯度计算以节省显存并加速推理，再通过 `torch.argmax(test_outputs, dim=1)` 得到预测类别索引。

### 五、 实际工程中的关键注意点

1. **空间对齐与量纲归一化**：数据级融合默认 `rgb` 与 `depth` 已经完成像素级空间对齐；真实数据中 RGB 通常经过均值/方差标准化，而深度图尺度不同，建议分别做好归一化后再拼接，避免量纲差异影响首层卷积梯度。
2. **掩码置零后的分布偏移**：将缺失模态直接乘 `0` 在数值上相当于引入了“零值深度”，若训练时缺失率较高，需留意 `BatchNorm` 统计量与特征激活分布的变化；在部分任务中也会结合可学习缺省值或特征级容错机制。
3. **模拟数据仅验证链路**：当前 `rgb_data`、`depth_data` 与 `labels` 均为随机张量，主要用于跑通模型结构与训练/推理闭环，真实任务需替换为已对齐的多模态数据集。
