多模态大模型（MLLM / LMM）的核心架构，围绕着“异构模态感知 → 跨模态语义对齐与融合 → 统一推理与决策 → 多模态输出/行动”**展开。结合前面讨论的架构设计与演进路线，可以从**四大核心组件、**主流融合范式**以及**架构设计权衡**三个维度进行系统概述：

---

### 一、 核心架构的四大组成模块

1. **模态编码器（Modality Encoder）**
* **职责**：将图像、视频、音频、3D 点云或传感器等非文本异构信号，转化为适合后续处理的高维特征序列或 Token。
* **常见做法**：视觉侧常用 ViT 及其变体或动态分辨率分块（Patchify）编码器；听觉侧常先转换为频谱图/梅尔频谱或声学/语义特征再编码；视频侧则进一步引入时空采样或时序建模。


2. **连接器 / 模态对齐模块（Connector / Alignment Module）**
* **职责**：充当非文本特征与语言模型（LLM）之间的桥梁，完成向量维度映射、跨模态语义对齐，并常承担 Token 长度压缩的任务。
* **典型形态**：
* **MLP / 线性投影**：结构简洁，直接映射特征，保留较多空间或序列细节。
* **可学习查询压缩（如 Q-Former / Resampler）**：利用可学习 Query 通过交叉注意力提炼固定长度特征，降低送入 LLM 的 Token 数量。
* **空间/时空压缩模块**：如局部合并、池化或动态切片重组，平衡细粒度感知与计算开销。




3. **语言模型基座 / 统一推理核心（LLM / Backbone）**
* **职责**：承接文本 Token 与对齐后的多模态表征，利用注意力机制完成上下文建模、跨模态语义关联、逻辑推理与指令遵循。
* **演进方向**：从“以文本 LLM 为核心外挂多模态”逐步向“原生多模态（Native Multimodal）统一序列/注意力建模”发展，部分架构还引入 MoE（混合专家）以在扩充容量时控制推理成本。


4. **生成器与行动解码器（Generator & Action Decoder）**
* **职责**：将基座模型的输出表征转化为非文本模态内容或具体行动指令，使模型从“理解并回答”走向“创造与执行”。
* **常见形态**：
* **多模态生成器**：如图像/视频扩散模型或音频/语音解码器，支持跨模态生成与编辑。
* **交互与行动头**：如输出屏幕坐标/操作的 GUI 智能体，或输出空间轨迹与控制动作的视觉-语言-动作（VLA）模块。





---

### 二、 三种主流架构融合范式

| 架构范式 | 工作机制 | 核心优势 | 主要局限 |
| --- | --- | --- | --- |
| **1. 编码器 + 连接器 + LLM（外挂/桥接式）** | 各模态先经独立编码器提取特征，再通过 MLP、Q-Former 等连接器映射到 LLM 空间联合推理。 | 模块解耦清晰，可复用现有强编码器与强 LLM 基座，迭代与扩展成本低。 | 分阶段“缝合”可能存在对齐瓶颈，高分辨率/长视频下 Token 序列较长。 |
| **2. 交叉注意力 / 层间深度融合式** | 通过 Cross-Attention 或注意力层内交互，让多模态特征与文本/隐状态在多层推理中直接关联。 | 支持细粒度特征回看与层间深度交互，有利于复杂定位、时序关联与多模态推理。 | 结构与跨层交互更复杂，计算与工程实现开销相对较高。 |
| **3. 原生多模态 / 统一词表与一体化式** | 在更早阶段联合建模多模态信号，或通过离散化/统一表征兼顾理解与生成、流式音视频或动作输出。 | 减少模态割裂，更易实现任意模态输入输出（Any-to-Any）、全双工实时交互与统一推理。 | 联合训练与多目标平衡难度大，对数据质量、算力与表征粒度统一要求极高。 |

---

### 三、 架构设计中的关键权衡

* **理解表征 vs. 生成表征**：理解任务偏重抽象语义与逻辑推理，生成任务偏重底层纹理、音色与重建保真度；如何在统一架构中兼顾两者是核心设计难题。
* **细节保真度 vs. Token 长度与延迟**：保留高分辨率、多帧或高采样率细节会带来长 Token 序列、高显存占用与较高首字延迟（TTFT）；依赖动态分辨率、Token 压缩与高效注意力在两者间寻优。
* **语言先验推理 vs. 跨模态证据锚定**：强大的语言底座带来优秀推理与指令能力，但也容易产生“模态捷径”或幻觉，需要通过细粒度对齐、多模态思维链与偏好优化加以约束。
