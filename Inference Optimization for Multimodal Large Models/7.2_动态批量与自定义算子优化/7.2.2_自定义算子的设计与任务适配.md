在模型推理优化中，**自定义算子**通过将高频子图合并、匹配硬件存储与计算特性、以及针对具体模型任务定制数据流，降低显存带宽瓶颈与内核启动开销。

---

### 一、 自定义算子的核心设计原则

1. **算子融合与访存最小化：** 推理阶段大量算子属于访存受限型（如 LayerNorm、RMSNorm、RoPE、激活函数与逐元素操作）。将相邻算子融合为单一 Kernel，让中间张量留在片上高速存储（Shared Memory / SRAM / 寄存器），避免反复读写高带宽显存（HBM）。
2. **对齐硬件存储层级与计算单元：**
* **分块（Tiling）：** 将大矩阵或序列切分为适配 Shared Memory 容量与 Tensor Core / 矩阵单元 tile 尺寸的小块，提升数据复用率。
* **合并访存与对齐：** 保证线程束（Warp）内访存连续且满足硬件向量化宽度（如 128-bit 加载/存储），减少访存事务次数。
* **双缓冲与流水线（Double Buffering / Pipeline）：** 重叠数据预取与计算执行，隐藏访存延迟。


3. **控制资源占用与调度粒度：** 合理权衡每线程块寄存器数量、Shared Memory 用量与活跃线程束数量（Occupancy），避免因资源溢出导致寄存器换出（Register Spilling）到显存，同时防止小张量下 Grid 过小无法铺满硬件计算单元。
4. **数值精度与鲁棒性：** 在 FP16、BF16、FP8 或 INT4/INT8 量化推理中，关键归约（如 Softmax、Norm、累加）常需在 FP32 中完成以抑制溢出或精度损失，并在边界形状、非连续张量（Strided Tensor）和极端数值下保持稳定。

### 二、 面向不同推理任务与场景的适配策略

| 推理任务 / 场景 | 核心瓶颈特征 | 自定义算子适配重点 | 典型算子形态 |
| --- | --- | --- | --- |
| **LLM 预填充（Prefill）** | 计算密集（大矩阵乘与长序列注意力），显存带宽压力相对较小 | 强化矩阵分块、Tensor Core 指令调度与长序列分块计算，降低中间注意力矩阵显存占用 | 分块注意力算子、融合投影与激活算子 |
| **LLM 解码（Decode）** | 访存受限（单步 Token 少、Batch 依赖 KV Cache 读取），小算子调度开销显著 | 减少 Kernel 启动次数，合并 KV Cache 更新与注意力读取，优化低 Batch 下的向量化访存与并行度 | 融合解码注意力算子、Paged KV 读写与 RoPE 融合算子 |
| **多模态与视觉任务** | 跨模态特征对齐、高分辨率特征图与变长 Patch 序列并存 | 消除动态形状带来的频繁重编译与 Padding 浪费，融合图像预处理、位置编码与注意力/卷积操作 | 变长序列注意力算子、融合归一化与下采样算子 |
| **量化与稀疏推理** | 低比特解压缩开销、非结构化或块稀疏索引访存不规则 | 在寄存器或片上完成反量化与矩阵乘融合，针对块稀疏模式设计专用索引加载与跳过计算逻辑 | W4A16 / FP8 融合 GEMM、块稀疏矩阵乘算子 |

### 三、 工程落地与验证流程

1. **性能剖析定位瓶颈：** 先通过 Profiling 工具识别耗时占比最高、显存带宽利用率异常或存在大量碎片化 Kernel 的子图，不盲目手写算子。
2. **优先评估高层编译器与算子库：** 在手写 CUDA / Triton 等底层算子前，先验证现有算子库或图编译器融合是否已满足延迟与吞吐目标；当存在特殊融合模式、非标准内存布局或特定量化格式时再定制算子。
3. **形状与动态性适配：** 推理输入常包含动态 Batch Size、动态序列长度或可变分辨率。需设计合理的分块启发式策略与多档 Kernel 调度，兼顾短序列低延迟与长序列高吞吐。
4. **正确性与性能双重回归：** 以参考实现为基准校验数值误差容限（关注余弦相似度、最大绝对误差与极端输入），并在真实业务负载下对比端到端延迟、吞吐量与显存峰值，而非仅看单算子微基准测试。
