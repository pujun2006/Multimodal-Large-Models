Multi-GPU Distributed Inference.py代码实现了一个**单机多 GPU 数据并行离线推理**流程：启动 `world_size` 个独立进程（每张 GPU 一个进程），各卡持有独立的 `SimpleModel` 副本，按分片并行处理 CIFAR-10 测试集，最后在 `rank == 0` 汇总去重并还原原始顺序。

---

## 一、 核心模块与执行流程拆解

### 1. 进程拉起与通信初始化（`main` / `setup` / `cleanup`）

* **`main()`：** 通过 `torch.cuda.device_count()` 获取可用 GPU 数量作为 `world_size`，使用 `mp.spawn(..., nprocs=world_size, join=True)` 拉起 `world_size` 个子进程，分别传入 `rank`（`0` 到 `world_size - 1`）。
* **`setup(rank, world_size)`：**
* 配置 `MASTER_ADDR` 与 `MASTER_PORT`（用 `setdefault` 保留外部环境变量覆盖能力）。
* 调用 `torch.cuda.set_device(rank)` 绑定当前进程默认 CUDA 设备，避免跨卡默认上下文混淆。
* 初始化 `torch.distributed.init_process_group(backend="nccl", ...)`，建立多卡集合通信组，并显式传入 `device_id`。


* **`cleanup()`：** 放在 `finally` 块中调用 `destroy_process_group()`，确保正常结束或异常退出时安全释放分布式通信资源。

---

### 2. 数据包装与并发安全准备（`IndexedDataset` / `prepare_dataset`）

* **`IndexedDataset`：** 继承 `torch.utils.data.Dataset`，在 `__getitem__` 中把原始样本索引 `idx` 一并带出。这是后续处理 `DistributedSampler` 补齐样本（padding）和还原原始顺序的关键。
* **`prepare_dataset(rank, root)`：**
* 定义 `Resize(32, 32)`、`ToTensor()` 和 CIFAR-10 三通道 `Normalize`。
* **防下载竞争：** 仅 `rank == 0` 执行 `download=True`；第一个 `torch.distributed.barrier()` 阻塞其他 `rank`，直到下载完成；随后非 0 进程以 `download=False` 读取本地数据，第二个 `barrier()` 保证所有进程就绪后再进入 `DataLoader`。



---

### 3. 数据分片与前向推理（`run_inference`）

* **`DistributedSampler(..., shuffle=False, drop_last=False)`：**
* 将数据集划分为 `world_size` 个子集，每个 `rank` 只读取自己负责的分片。
* `shuffle=False` 保持推理顺序稳定；`drop_last=False` 保留末尾不足一个 `batch_size` 的样本。


* **`DataLoader(..., num_workers=2, pin_memory=True)`：** 使用锁页内存（pinned memory）与多 worker 预取，配合 `inputs.to(device, non_blocking=True)` 加速 Host 到 Device 的数据传输。
* **推理上下文：** 模型移至 `device` 并设为 `model.eval()`（关闭 Dropout、BatchNorm 统计更新等训练行为），在 `with torch.inference_mode():` 下执行前向计算与 `torch.argmax(outputs, dim=1)` 取预测类别。

---

### 4. 结果汇总、去重与排序

* **通信收集：** 各进程将本地 `(idx, pred)` 二元组列表传入 `torch.distributed.all_gather_object(gathered_pairs, ...)`，使所有进程（重点是 `rank == 0`）拿到完整分片结果。
* **去重与还原：**
* `DistributedSampler` 为了让各卡样本总数对齐，会在尾部重复填充少量样本。
* 在 `rank == 0` 中用字典 `merged` 按 `idx` 收集，过滤 `idx >= original_len` 的填充项并对已存在 `idx` 去重，最后按 `range(original_len)` 索引构造 `ordered_preds`，保证与单卡顺序推理结果完全一致。



---

## 二、 关键工程细节与适用边界

* **为何不使用 `DDP`：** `DistributedDataParallel` 主要用于训练阶段的梯度同步（AllReduce）；纯推理只需各卡独立前向，去掉 `DDP` 可减少不必要的封装与通信开销。
* **为何需要 `idx` 去重：** 当 `original_len` 不能被 `world_size` 整除时，直接拼接各卡输出会导致样本数偏多或顺序错乱；记录全局索引是离线数据并行推理最稳妥的做法之一。
* **适用与局限：** 适合**单机多卡、模型可放入单张 GPU 显存、输入样本相对规整的离线批量推理**。若遇到大模型单卡放不下（需张量并行/流水线并行）或高并发在线流式请求（需连续批处理与显存/KV Cache 调度），则需要更专业的分布式推理引擎或并行策略。
