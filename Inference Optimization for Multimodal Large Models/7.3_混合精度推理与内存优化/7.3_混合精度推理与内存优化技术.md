现代深度学习与大模型推理的核心瓶颈往往不在算力峰值，而在**显存容量**与**显存带宽**。混合精度推理与内存优化通过降低数值位宽、减少重复计算和消除内存碎片，在可控精度损失下换取更高的吞吐与更低的延迟。

---

## 一、 混合精度推理核心机制

混合精度推理指在模型前向计算中，对不同张量或算子采用不同数值格式（如 `FP32`、`FP16`、`BF16`、`FP8`、`INT8`、`INT4`），兼顾数值动态范围与硬件计算吞吐。

### 1. 主流数值格式对比

| 格式 | 符号位 + 指数位 + 尾数位 | 动态范围与精度特点 | 典型推理定位 |
| --- | --- | --- | --- |
| **FP32** | `1 + 8 + 23` | 动态范围广、精度高，但显存占用大、带宽消耗高 | 关键累加、数值敏感层或参考基线 |
| **FP16** | `1 + 5 + 10` | 吞吐高，但指数位少（最大约 `65504`），易下溢或溢出 | 早期 GPU 通用半精度推理（常需缩放/校准） |
| **BF16** | `1 + 8 + 7` | 指数位与 `FP32` 相同，抗溢出能力强，尾数精度较低 | 大模型训练与现代 GPU 推理（减少溢出风险） |
| **FP8 (E4M3 / E5M2)** | `1 + 4 + 3` / `1 + 5 + 2` | `E4M3` 精度更高适合权重/激活，`E5M2` 范围更广适合梯度/动态范围大的张量 | Hopper 及更新架构的高吞吐矩阵乘（GEMM） |
| **INT8 / INT4** | 整数定点数（8 位 / 4 位） | 访存与计算开销极低，强依赖量化缩放因子（Scale）与零点（Zero-point） | 权重压缩、高并发吞吐优先场景 |

### 2. 量化与计算路径设计

* **对称量化与非对称量化：** 通过缩放因子将浮点张量映射到整数区间，常见粒度包括逐张量（Per-Tensor）、逐通道（Per-Channel）和逐分组（Per-Group，如 `INT4` 每 128 个权重共享一组缩放参数以抑制离群值误差）。
* **W8A8 / W4A16 / FP8 推理：**
* **W4A16（权重 4 位、激活 16 位）：** 主要缓解解码阶段权重搬运的显存带宽瓶颈，反量化通常与矩阵乘融合执行。
* **W8A8 / FP8：** 权重与激活均以低位宽参与计算，能在支持对应 Tensor Core 的硬件上进一步提升计算吞吐。


* **敏感层回退：** LayerNorm/RMSNorm、Softmax、注意力分数累加、Embedding 或部分易出现离群通道（Outlier Channels）的投影层，常保留高精度（如 `FP16`/`BF16`/`FP32`）以稳住输出分布。

## 二、 显存占用构成与核心优化技术

在自回归推理中，显存主要由**模型权重**、**KV Cache**、中间激活与工作区（Workspace）三部分组成。随着上下文长度与并发批大小增长，KV Cache 往往成为长上下文场景的最大显存占用项。

---

### 1. KV Cache 管理与分页化

* **KV Cache 复用机制：** 在自回归生成时，历史 Token 的 Key 和 Value 向量在后续步骤中保持不变。缓存后只需为新输入 Token 计算 K/V 并与历史缓存拼接，避免重复计算。
* **PagedAttention 与块级管理：** 传统连续预分配 KV Cache 容易因序列长度动态变化产生内部碎片与外部碎片。通过将 KV Cache 切分为固定大小的物理块（Block），并由块表（Block Table）映射到逻辑位置，可按需分配内存并支持前缀共享（如相同 System Prompt 或多轮共享上下文）。
* **KV Cache 压缩与结构精简：**
* **GQA / MQA：** 多组查询头共享较少数量的 K/V 头，直接降低每 Token 的 KV Cache 字节数与解码访存量。
* **KV 量化：** 将 K/V 缓存从 `FP16`/`BF16` 量化为 `FP8` 或 `INT8`，在长窗口下显著扩容可承载的并发请求数。



### 2. 算子融合与激活内存控制

* **算子融合（Operator Fusion）：** 将相邻的线性变换、激活函数、归一化或反量化操作合并为单个 Kernel，减少中间张量写回显存与再次读取的次数，同时降低临时激活显存峰值。
* **FlashAttention 类分块计算：** 通过在片上高速缓存（SRAM）内对 `Q`、`K`、`V` 进行分块（Tiling）计算并在线维护 Softmax 统计量，避免物化完整的 $N \times N$ 注意力矩阵，大幅降低显存占用并提升访存效率。
* **动态批处理与显存池复用：** 结合连续批处理（Continuous Batching）提高 GPU 利用率，配合内存池复用临时缓冲区与引擎 Workspace，减少频繁申请/释放显存带来的开销与碎片。

---

## 三、 工程落地时的关键权衡

1. **吞吐、延迟与精度的三角平衡：** 更激进的低比特量化（如 `INT4`）能显著压低显存与带宽占用，但可能在复杂推理、数学/代码生成或长尾分布上带来精度下降；上线前需用代表性校准集与评测集验证。
2. **算子支持与运行时对齐：** 混合精度能否转化为实际加速，取决于目标硬件架构、底层算子库对特定数据类型的原生支持，以及图编译/引擎构建时的动态 Shape 优化配置。
3. **阶段特征差异：** Prefill（首字延迟 TTFT）更偏向算力密集型，Decode（逐字生成 TPOT）更偏向访存带宽与 KV Cache 容量受限，优化策略应分别针对两阶段瓶颈展开。
