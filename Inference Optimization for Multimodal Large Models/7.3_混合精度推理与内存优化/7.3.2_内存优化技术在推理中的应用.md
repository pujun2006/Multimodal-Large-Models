在模型推理中，**内存（显存）优化技术**的核心任务是降低**模型权重**、**KV Cache**与**临时激活值**的存储与带宽占用。

与训练不同，推理没有反向传播与优化器状态，但面临**高并发**、**长上下文**与**低延迟**的严苛约束。大模型自回归解码阶段往往处于**访存瓶颈（Memory-Bound）**：每生成一个 token，都需要将大量权重和历史 KV Cache 从高带宽显存（HBM）搬运至计算单元。因此，减少字节数不仅释放容量，还能直接缩短访存时间、提升吞吐量。

---

## 一、 推理内存的三大组成

1. **模型权重（Weights）**：静态占用，随参数量与位宽线性增长。
2. **KV Cache（键值缓存）**：动态增长，随 batch size、序列长度、层数与 KV 头数增长；长文本或高并发下常超越权重成为最大显存杀手。
3. **中间激活与工作区（Activations / Workspace）**：随序列长度与算子融合程度波动，在预填充（Prefill）阶段与算子临时缓冲中尤为明显。

---

## 二、 权重与激活值压缩技术

### 1. 推理量化（Quantization）

* **权重量化（W8A16、W4A16）**：将权重压缩为 `INT8` 或 `INT4`（如 GPTQ、AWQ、GGUF），反量化后与 `FP16`/`BF16` 激活计算。权重显存可降至原来的 $1/2$ 到 $1/4$，特别适合 decode 阶段缓解访存瓶颈。
* **权重与激活联合量化（W8A8 / FP8）**：权重与激活均采用低精度（如 `INT8` 或 `FP8`），直接利用硬件低精度矩阵乘指令（如 Tensor Core），兼顾显存节省与计算加速；对离群通道（outlier channels）通常需要平滑（SmoothQuant）或逐通道/逐组缩放以控制精度损失。

### 2. 结构化剪枝与算子融合

* **结构化剪枝 / 稀疏化**：移除冗余通道、注意力头或专家路由，直接减少权重体积与计算量；硬件支持半结构化稀疏时可进一步压缩访存。
* **算子融合（Operator Fusion）**：将相邻小算子（如激活函数、归一化、残差相加或部分线性变换）合并进单一 kernel，避免中间张量反复写回显存并减少 kernel 启动开销。

## 三、 KV Cache 内存优化技术

自回归生成时，历史 token 的 Key 和 Value 无需重复计算，但缓存体积随上下文增长迅速。

| 优化方向 | 核心做法 | 主要收益与代价 |
| --- | --- | --- |
| **分页与块管理** | 借鉴虚拟内存分页思想，将 KV Cache 切分为固定大小的物理块，按需分配与映射（如 PagedAttention 机制） | 消除连续预分配导致的内部/外部碎片，支持前缀共享与动态扩容，增加页表映射与访存间接性 |
| **注意力结构压缩** | 采用分组查询注意力（GQA）或多查询注意力（MQA），让多个 Query 头共享同一组 Key/Value 头 | 大幅降低单 token 的 KV Cache 字节数与 decode 访存量；通常在预训练或微调阶段定型 |
| **KV 量化与驱逐/压缩** | 将 KV 存为 `FP8` 或 `INT4`，或对长上下文做滑动窗口、Sink Token 保留与重要 token 驱逐/合并 | 显著拉长可承载上下文或提高并发度；激进驱逐或低比特量化可能影响长程检索精度 |
| **前缀缓存（Prefix Caching）** | 缓存公共 System Prompt、Few-shot 或多轮共享前缀的 KV 块，命中时直接复用 | 减少重复 Prefill 计算与首字延迟（TTFT），需管理缓存命中率与淘汰策略 |

---

## 四、 系统级内存调度与协同优化

* **连续批处理（Continuous Batching）与抢占/换出（Swap）**：请求动态进出 batch；当显存紧张时，可将部分序列的 KV Cache 换出（Offload）至主机内存（CPU RAM），或暂停低优先级请求，避免直接触发 OOM（内存溢出）。
* **权重卸载（CPU / NVMe Offloading）**：在单卡显存不足以容纳大模型时，按层或按块流式将权重从 CPU 内存或 NVMe 加载到 GPU 显存计算，以吞吐换取可运行性，需配合异步拷贝与流水重叠尽量掩盖传输延迟。
* **静态内存池与图捕获（CUDA Graph）**：复用预分配显存块减少频繁 `malloc/free` 带来的碎片；结合静态计算图减少 CPU 调度开销，使内存分配与访存模式更可预测。

---

## 五、 工程选型建议

* **显存受限且追求高吞吐（Decode 主导）**：优先评估 **W4A16 / W8A16** 权重量化 + **分页 KV 管理** + **Continuous Batching**。
* **长上下文与高并发场景**：重点关注 **GQA/MQA**、**KV Cache 量化/前缀缓存** 与 **显存碎片控制**，防止 KV 膨胀挤占 batch 空间。
* **精度敏感任务（如复杂推理、代码、数学）**：先从 `FP16`/`BF16` 或 `FP8`/高分组 `INT4` 起步，逐项对比基准评测指标与长文本退化情况，切忌盲目追求极低位宽。
