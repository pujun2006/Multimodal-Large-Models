RLHF.py代码实现了一个**端到端的基于人类反馈的强化学习（RLHF）最小可运行原型**，基于 PyTorch 和 Hugging Face `transformers`（默认使用 `gpt2`）。整个流程分为三个核心阶段：**监督微调（SFT）**、**奖励模型训练（Reward Model）**和**带 KL 惩罚的强化学习微调（RL Policy Gradient）**。

---

### 一、基础环境与分词器准备

* **`get_device()`**：按优先级自动检测可用硬件加速设备：CUDA（NVIDIA GPU） → MPS（Apple Silicon） → CPU。
* **`setup_tokenizer(model_name)`**：加载分词器并处理 GPT-2 缺乏填充符（`pad_token`）的问题。将其设为 `eos_token`，这样在批量处理不等长序列时既能对齐长度，又不会引入额外的新词表向量。

---

### 二、第一阶段：监督微调（SFT）

目标是让基础语言模型学会遵循 `Question / Answer` 的指令格式与基本回答模式。

#### 1. `SFTDataset`

* 将 `(prompt, response)` 拼接为完整输入序列 `input_ids`，并在 `response` 末尾补上 `eos_token`。
* **标签掩码（Label Masking）**：将 `prompt` 对应位置以及右侧填充（`pad`）位置的 `labels` 设为 `-100`。PyTorch `CrossEntropyLoss` 默认忽略 `-100`，因此**只计算模型生成回答部分的交叉熵损失**，避免强迫模型去“预测”提示词本身。

#### 2. `train_sft`

* 使用 `AdamW` 优化器更新整个 `policy_model` 参数，并通过 `clip_grad_norm_(..., 1.0)` 做梯度裁剪，防止早期微调出现梯度爆炸。

---

### 三、第二阶段：奖励模型（Reward Model）

目标是训练一个打分器 $r_\theta(x, y)$，使其对“更符合人类偏好的回答（`chosen`）”给出高于“较差回答（`rejected`）”的标量分数。

#### 1. `RewardModel`

* 拷贝基座模型作为 `self.backbone`，并将原本输出词表概率分布的 `lm_head` 替换为 `nn.Identity()`。
* 新增标量输出头 `self.score_head = nn.Linear(hidden_size, 1, bias=False)`。
* **池化取值（Last-token Pooling）**：从最后一层隐藏状态 `last_hidden` `[B, T, H]` 中，根据 `attention_mask.sum(dim=1) - 1` 定位每个样本**最后一个非 padding token** 的向量，再投影为单个标量奖励 `[B]`。在因果语言模型中，最后一个有效 token 汇聚了整段上下文的信息。

#### 2. `PreferenceDataset` 与 `train_reward_model`

* 将 `prompt + chosen + eos` 与 `prompt + rejected + eos` 分别编码。
* 采用 **Bradley-Terry 偏好损失**，最大化优选回答与劣选回答的奖励差值：

$$\mathcal{L}_{\text{RM}} = -\mathbb{E}\left[\log \sigma(r_\theta(y_w) - r_\theta(y_l))\right] = \mathbb{E}\left[\text{softplus}\big(-(r_\theta(y_w) - r_\theta(y_l))\big)\right]$$

* 同时统计 `Pair Acc`（`r_chosen > r_rejected` 的比例），用于观察奖励模型区分优劣回答的准确率。

---

### 四、第三阶段：带 KL 惩罚的策略梯度微调（RL）

直接最大化奖励模型分数容易导致**奖励劫持（Reward Hacking）**（例如模型输出乱码或重复词来刷高分）。因此需要引入冻结的参考模型 `ref_model`（即 SFT 后的模型）施加 KL 散度约束，防止策略偏离语言常识太远。

#### 1. `compute_response_logprob_sum`

* 对完整序列做因果移位对齐：`logits[:, :-1, :]` 预测目标 `targets = full_ids[:, 1:]`。
* 通过 `log_softmax` 和 `gather` 取出每个目标 token 的对数概率，随后用 `resp_mask` 过滤掉 prompt 部分与 padding 部分，最后对回答区域求和，得到每条回答的对数概率总和 $\log \pi(y \mid x)$。

#### 2. `train_rl_policy` 的核心步骤

1. **左填充批量生成（Left Padding）**：因果模型做批量文本生成时，左填充能让所有序列的最后一个 token 对齐到同一位置，便于并行解码；生成结束后恢复原始 `padding_side`。
2. **评估与参考对数概率计算**：在 `torch.no_grad()` 下，用 `rm` 计算生成序列的奖励 `rm_scores`，并用 `ref_model` 计算参考对数概率 `ref_resp_logp`。
3. **奖励塑形（Reward Shaping）与优势归一化**：
* 近似序列级 KL 散度（并截断到 $[-20, 20]$ 增强数值稳定性）：
$$\text{KL} \approx \log \pi_\theta(y \mid x) - \log \pi_{\text{ref}}(y \mid x)$$


* 计算带 KL 惩罚的奖励：
$$R_{\text{shaped}} = r_\phi(x, y) - \beta \cdot \text{KL}$$


* 减去批次均值作为基线并做标准化（减均值除标准差），降低策略梯度的方差、稳定训练步长。


4. **策略梯度更新**：最小化 $-\text{advantage} \times \text{policy\_resp\_logp}$，推动高优势回答的概率上升、低优势回答的概率下降。

---

### 五、主流程

`__main__` 部分串起了完整链路：`SFT` → 复制权重得到 `ref_model` 与初始化 `reward_model` → 训练 `reward_model` → 用 `rl_prompts` 做策略优化 → 用测试 prompt 验证生成结果。

### 七、 潜在改进点
若要将其从教学/实验代码推进到更贴近工业实践的 PPO/RLHF 训练，通常还会关注以下几点：

* **Token 级别 KL 与 PPO Clip**：当前代码使用的是**序列级**近似 KL 和单步 REINFORCE 风格策略梯度；标准 PPO 会在每个生成 token 上施加逐 token KL 惩罚，并使用重要性采样比率（ratio）与 `clip` 限制单次更新幅度。
* **数据集规模与评估集**：示例中的 `sft_data`、`pref_data`、`rl_prompts` 各只有 2 条样本，仅用于验证代码通路与梯度流动，实际训练需要成千上万条高质量样本及独立的验证集。
* **奖励模型与策略模型容量/训练轮次**：小样本下 `rm` 容易过拟合偏好数据，实际使用中常需监控验证集 Pair Acc 防止过拟合。
