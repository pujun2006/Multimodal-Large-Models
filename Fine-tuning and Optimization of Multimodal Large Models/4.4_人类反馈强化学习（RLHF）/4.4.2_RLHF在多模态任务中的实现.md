在多模态任务（以视觉-语言模型 VLM 为典型代表，如图文问答、看图描述、多模态推理等）中实现 **RLHF**，核心框架仍然延续纯文本 RLHF 的 **SFT → Reward Model → RL 优化** 三阶段范式，但因为引入了**图像/视频/音频等非文本模态**，在**输入编码与序列拼接、幻觉抑制、偏好数据构造、奖励建模与策略更新**等环节都面临显著不同的工程与算法细节。

---

### 一、多模态 RLHF 相比纯文本的关键差异与痛点

1. **视觉/多模态幻觉（Hallucination）严重**：语言模型即使“瞎编”图像中不存在的物体、颜色或文字，有时在语言流畅度上依然看似合理。若奖励模型只看文本质量，RL 反而可能鼓励模型写得更长、更自信，从而放大幻觉。
2. **模态失衡与“语言先验捷径”**：VLM 容易过度依赖文本指令的统计规律或语言先验，忽视图像中的细微视觉证据。偏好数据需要专门构造“视觉强依赖”样本（例如细微属性差异、计数、空间关系、OCR 细节）。
3. **多模态输入拼接与长度爆炸**：图像经过 Vision Encoder 和 Projector 后会变成数十到上千个视觉 token，与文本 token 交织在一起。训练时不仅显存占用更高，还要准确划分**多模态 prompt 边界**，确保 loss 和 KL 只作用于模型生成的文本回答部分。
4. **不同模块的可训练性差异**：VLM 通常包含 Vision Encoder、跨模态 Projector/Connector 以及 LLM Backbone。在 SFT、RM 和 RL 阶段，需要决定哪些组件冻结、哪些解冻（例如常见做法是冻结 Vision Encoder 或仅微调 Projector + LLM / LoRA）。

### 二、多模态 RLHF 的四步实现流程

#### 1. 构造多模态偏好数据（三元组 / 图像级对比）

多模态偏好样本通常表示为 $(I, x, y_w, y_l)$，其中 I 为图像（或多模态输入），x 为文本问题/指令，y_w 为优选回答，y_l 为劣选回答。常见构造方式包括：

* **人工标注 + 事实核查**：让标注员对照原图评估多个候选回答，重点扣分“图中未出现的物体/属性”或“答非所问”。
* **定向制造幻觉负样本**：对同一张图生成包含篡改属性或虚构细节的回答作为 $y_l$，逼迫模型和奖励模型真正“看图说话”。
* **多模型采样与自动/半自动筛选**：用不同温度或不同模型对同一 `(I, x)` 生成多个候选，结合视觉定位/OCR/规则或强模型打分初步过滤，再由人工精标。

#### 2. 多模态监督微调（Multimodal SFT）

在进入 RL 之前，先用高质量 `(I, x, y)` 指令数据进行 SFT，让模型掌握多模态指令遵循与结构化输出能力：

* **输入组织**：将图像特征嵌入插入文本序列的占位符位置（如 `<image>` 标记展开为视觉 token），拼接系统指令、用户问题 $x$ 和目标回答 $y$。
* **Loss Masking**：与纯文本 `SFTDataset` 原理一致，将所有视觉 token、文本 prompt token 以及 `pad` token 对应的 `labels` 设为 `-100`，**仅在回答 $y$ 的 token 上计算交叉熵损失**。

#### 3. 多模态奖励模型（Multimodal Reward Model）

多模态奖励模型 $r_\phi(I, x, y)$ 必须同时理解图像内容 $I$、问题 $x$ 与回答 $y$ 是否一致：

* **架构设计**：通常基于同源 VLM 初始化（去掉 `lm_head`，在最后一层最后一个有效 token 位置接线性打分头输出标量奖励），或采用生成式/打分式融合结构。
* **训练目标**：同样使用成对偏好的 **Bradley-Terry 损失**：

$$\mathcal{L}_{\text{RM}} = -\mathbb{E}_{(I, x, y_w, y_l)}\left[\log \sigma\big(r_\phi(I, x, y_w) - r_\phi(I, x, y_l)\big)\right]$$

* **防过拟合与视觉 grounding**：多模态 RM 容易把“回答长度”或“句式模板”当成高分特征。训练时需注意长度平衡、多样化负样本，并在验证集上监控不同题型（如物体存在性、计数、推理）的 Pairwise Accuracy。

#### 4. 多模态强化学习微调（RL Policy Optimization）

在 RL 阶段，策略模型 $\pi_\theta(y \mid I, x)$ 针对多模态输入 $(I, x)$ 采样生成回答 $y$，参考模型 $\pi_{\text{ref}}$ 保持冻结：

* **采样与参考概率计算**：
* 生成阶段同样建议使用 **left padding** 保证批量解码对齐。
* 评估 `rm_scores` 时传入完整多模态序列（包含图像输入与生成的文本）；计算 `ref_resp_logp` 和 `policy_resp_logp` 时，**只对生成的文本回答区间求和**，排除视觉 token 与 prompt token。


* **KL 惩罚与奖励塑形**：

$$R_{\text{shaped}}(I, x, y) = r_\phi(I, x, y) - \beta \, D_{\text{KL}}\big(\pi_\theta(\cdot \mid I, x) \,\Vert{}\, \pi_{\text{ref}}(\cdot \mid I, x)\big)$$

其中 $\beta$ 控制偏离参考模型的惩罚强度。若 $\beta$ 过小，模型容易出现视觉幻觉或语言退化；若 $\beta$ 过大，模型难以吸收偏好信号。

* **优化算法选择**：除了经典的 PPO（Actor-Critic 架构，需额外训练 Critic Value 模型），多模态实践中也常采用 GRPO 等组内相对优势估计或直接偏好优化类方法（如 DPO/多模态变体），以降低额外 Value 网络的显存与调参成本。

### 三、多模态 RLHF 与纯文本 RLHF 对比

| 维度 | 纯文本 RLHF | 多模态 RLHF（以 VLM 为例） |
| --- | --- | --- |
| **核心输入** | 文本 prompt $x$ | 多模态输入 $(I, x)$（图像/视频 + 文本） |
| **主要对齐痛点** | 编造事实、语气不当、拒答过度/不足 | 视觉幻觉、忽略图像细节、依赖语言先验 |
| **模型组件** | 通常是单一 LLM | Vision Encoder + Projector/Adapter + LLM |
| **序列长度与显存** | 相对可控，文本 token 较紧凑 | 视觉 token 数量多，显存开销和序列长度更大 |
| **RM 关注点** | 逻辑性、有用性、无害性 | 图文一致性、细节准确性、指令遵循 |

### 四、落地时的关键工程细节

* **数据混合比例**：RL 阶段若只用某一类多模态数据（如只用看图说话），模型可能在其他能力上退化；通常需要混合 VQA、描述、推理及少量纯文本指令数据。
* **阶段性解冻策略**：显存受限时，常冻结 Vision Encoder，只微调 LLM（或 LoRA）与跨模态连接层；若涉及新领域图像（如医学影像、图表、复杂 UI），可能需要适度放开视觉侧或先做针对性 SFT。
* **离线评测指标**：除了奖励模型得分与 KL 散度，务必在独立多模态评测集上跟踪**幻觉率**（如 POPE 类存在性测试或人工抽检）以及通用 VQA 准确率，防止“奖励虚高但实际视觉准确率下降”。
