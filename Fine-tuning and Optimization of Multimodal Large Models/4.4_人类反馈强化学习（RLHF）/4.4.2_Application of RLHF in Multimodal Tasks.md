4.4.2_Application of RLHF in Multimodal Tasks.py代码实现了一个**端到端可运行的多模态大模型后训练（Post-Training / Alignment）原型**，完整串联了 **多模态监督微调（MM-SFT）**、**多模态偏好奖励模型（MM-RM）** 与 **带 KL 惩罚的强化学习策略梯度微调（MM-RL / REINFORCE + KL）** 三个核心阶段。

整体采用轻量组合（`ResNet-50` 视觉编码器 + `GPT-2` 因果语言模型），并在缺少本地图片时自动生成确定性的伪随机 RGB 图像，便于在本地或离线环境下快速验证训练流程与张量维度对齐。

---

### 一、 基础工具与多模态核心模型

#### 1. 环境与图像处理工具

* **`set_seed` / `get_device` / `setup_tokenizer**`：统一随机种子；按 CUDA → MPS → CPU 优先级选择设备；若 Tokenizer 无 `pad_token`（如 GPT-2 默认没有），则将其设为 `eos_token`。
* **`load_image_tensor`**：将图像统一调整为 `[3, 224, 224]` 并按 ImageNet 均值与标准差归一化。若路径不存在，则用路径哈希作为种子生成确定性假图像，保证示例脚本不会因缺图报错。

#### 2. `MultiModalVisionEncoder`

* 使用 `ResNet-50` 去掉最终分类全连接层（`[:-1]`），提取 `[B, 2048, 1, 1]` 特征并 `flatten(1)` 为 `[B, 2048]`。
* 通过 `Linear -> GELU -> Linear` 投影层将特征映射到与语言模型一致的 `hidden_size`（`[B, H]`），实现视觉与文本隐空间的维度对齐。

#### 3. `MultiModalPolicyLM`（Soft Prompt / Prefix 视觉注入）

* **拼接机制（`_build_mm_inputs`）**：将视觉特征 `unsqueeze(1)` 变为 **1 个视觉 Token**（`[B, 1, H]`），拼接在文本 Embedding（`[B, T, H]`）最前面，得到 `[B, 1 + T, H]`；对应的 `attention_mask` 也在最前方补 `1`（`[B, 1 + T]`）。后续文本 Token 在因果自注意力中可关注该视觉 Token。
* **`forward_sft`**：在 `labels` 最前方补 `-100`（`vis_ignore`），使视觉 Token 位置不参与交叉熵损失计算。
* **`forward_logits`**：前向后切片 `outputs.logits[:, 1:, :]`，剔除第 0 个视觉 Token 对应的输出位，使输出与 `input_ids` 的 `[B, T, V]` 严格对齐。
* **`generate_response`**：基于视觉前缀 + 文本 Prompt 进行自回归循环，每步计算最后一个位置的 `logits`、施加 `temperature` 缩放与 **Top-p（核采样）**，并维护 `finished` 状态跟踪已生成 `eos_token_id` 的样本（已完成样本后续补 `pad_token_id`，且 `next_step_mask` 置 `0`）。

### 二、 三阶段后训练流程详解

| 阶段 | 核心组件与函数 | 目标与损失函数 | 关键细节 |
| --- | --- | --- | --- |
| **1. 多模态 SFT** | `MultimodalSFTDataset`<br>

<br>`train_multimodal_sft` | 让模型学会根据图像和指令输出符合格式的回答（标准交叉熵 Loss） | `labels` 中 Prompt 部分与 Padding 部分均设为 `-100`，仅对 Response 部分计算损失 |
| **2. 奖励模型（RM）** | `MultiModalRewardModel`<br>

<br>`MultimodalPreferenceDataset`<br>

<br>`train_multimodal_reward_model` | 给“图像 + Prompt + 回答”打标量分，使 `chosen` 得分高于 `rejected`；采用 **Bradley-Terry** 损失：$\mathcal{L} = -\mathbb{E}[\log \sigma(r_{\text{chosen}} - r_{\text{rejected}})]$，代码中使用数值更稳定的 `F.softplus(-(r_chosen - r_rejected)).mean()` | 深拷贝策略模型并将 `lm_head` 替换为 `nn.Identity()`，取最后一个有效非 Padding Token 的最后一层隐状态经 `score_head` 输出标量分数 |
| **3. 带 KL 惩罚的 RL** | `compute_response_logprob_sum`<br>

<br>`train_multimodal_rl_policy` | 提升 RM 奖励同时限制偏离参考模型（`ref_model`）过远；采用带基线/标准化优势的策略梯度：`pg_loss = -(advantage * policy_resp_logp).mean()` | 采样阶段临时将 `tokenizer.padding_side = "left"` 以适配批量自回归生成；`shaped_reward = rm_scores - kl_beta * kl` 后做零均值单位方差标准化 |

#### `compute_response_logprob_sum` 的对齐逻辑

* `logits[:, :-1, :]` 预测的是 `full_ids[:, 1:]`（即第 $t$ 个输出预测第 $t+1$ 个 Token）。
* 通过 `positions >= (prompt_lengths - 1)` 掩码出属于回复（Response）部分的预测步，再与非 Padding 掩码 `not_pad` 取交集，仅对回复 Token 的对数概率求和，得到每条样本回复序列的总对数概率 `[B]`。

### 三、 潜在坑点与工程改进建议

1. **RL 阶段 `prompt_lengths` 的左填充细节**：在 `train_multimodal_rl_policy` 中，`prompt_ids` 使用了 `padding_side="left"`，但 `prompt_lengths` 直接设成了 `prompt_ids.size(1)`（包含左侧 pad 长度）。由于左侧 pad 在生成阶段原本就是上下文前缀的一部分，这样写能对齐拼接后的序列长度，但在真实多轮或复杂模板中建议按实际有效长度精细核对。
2. **RL 批大小与采样稳定性**：`__main__` 中 `rl_samples` 仅有 2 条样本，每轮做一次全量采样与单步策略梯度更新（类似 REINFORCE / 简化 PPO 一步更新）；实际训练中通常会增加 Rollout 数量、使用多轮 Mini-batch 更新或 GRPO/PPO 裁剪机制以降低方差。
3. **视觉信息粒度**：当前仅用全局池化后的 **1 个视觉 Token**（`[B, 1, H]`）表示整张图像，适合演示原理；在真实多模态大模型（VLM）中，通常会保留空间网格特征（如 ViT Patch Tokens 或特征图展平后的多个视觉 Token）以保留细粒度视觉细节。
