Application of RLHF in Multimodal Tasks.py这段代码实现了一个**端到端可运行的“多模态大模型对齐训练原型（Multimodal SFT → Reward Model → KL-REINFORCE）”**。它以 `ResNet-50` 作为视觉编码器、以 `GPT-2`（或任意 HuggingFace `AutoModelForCausalLM`）作为语言基座，演示了视觉前缀注入与三阶段对齐的核心流程。

---

## 一、 核心架构与视觉前缀注入

多模态对齐的关键在于让**视觉特征**进入语言模型的自注意力上下文。代码通过 `MultiModalVisionEncoder` 和 `MultiModalPolicyLM` 实现了最简洁的**单视觉 Token 前缀拼接（Prefix Tokenization）**：

1. **视觉特征提取与投影（`MultiModalVisionEncoder`）**
* 使用 `resnet50` 去掉最后的分类头（`[:-1]`），将 `[B, 3, 224, 224]` 图像编码为 `[B, 2048, 1, 1]`，经 `.flatten(1)` 展平为 `[B, 2048]`（即使 `B=1` 也能安全保留 batch 维度）。
* 经过两层 `Linear` + `GELU` 投影头映射到与语言模型一致的 `hidden_size`（如 GPT-2 的 `768`），得到 `[B, H]` 向量。


2. **多模态序列拼接（`_build_mm_inputs`）**
* 将视觉向量 `unsqueeze(1)` 变为 `[B, 1, H]`，拼在文本词向量 `txt_emb` (`[B, T, H]`) 最前面，形成长度为 `1 + T` 的 `inputs_embeds`。
* 同步在 `attention_mask` 最前方补 `1`（`vis_mask`），使后续文本 Token 在因果注意力中能看到这个视觉前缀。


3. **离线可运行设计（`load_image_tensor` & `setup_tokenizer`）**
* 若本地图片不存在，会自动基于路径哈希生成确定性的合成 RGB 图像，方便无图环境下直接跑通流程；若分词器缺少 `pad_token`，则回退使用 `eos_token`。

## 二、 三阶段训练流程拆解

### 1. 多模态监督微调（MM-SFT）

* **数据与掩码（`MultimodalSFTDataset`）**：拼接 `prompt_ids` 与 `resp_ids + [eos_token_id]`。`labels` 中 **prompt 部分、padding 部分均设为 `-100**`，且在 `forward_sft` 中**再在最前方补一个 `-100**` 对应视觉 Token，确保交叉熵损失只在**回答（response）Token** 上计算。
* **训练循环（`train_multimodal_sft`）**：使用 `AdamW` 优化全量参数（视觉编码器、投影层与语言模型），并做梯度裁剪（`clip_grad_norm_=1.0`）。

### 2. 多模态奖励模型（MM-RM，Bradley-Terry 偏好建模）

* **结构改造（`MultiModalRewardModel`）**：深拷贝 SFT 后的 `policy_model`，把 `lm.lm_head` 替换为 `nn.Identity()`，取最后一层隐藏状态 `last_hidden` 中**最后一个有效非 padding Token**（通过 `mm_mask.sum(dim=1) - 1` 定位）的向量，接线性层 `score_head` 输出标量奖励分 `[B]`。
* **成对偏好损失（`train_multimodal_reward_model`）**：对同一图像与 prompt 的 `chosen` 和 `rejected` 分别打分得到 $r_{\text{chosen}}$ 与 $r_{\text{rejected}}$，最小化 Bradley-Terry 负对数似然：

$$\mathcal{L}_{\text{RM}} = \mathbb{E}\left[\log\left(1 + \exp(-(r_{\text{chosen}} - r_{\text{rejected}}))\right)\right] = \text{softplus}(-(r_{\text{chosen}} - r_{\text{rejected}}))$$



同时统计成对准确率（Pair Acc），监控奖励模型是否能正确区分优劣回答。

### 3. 带 KL 惩罚的多模态强化学习微调（MM-RL）

* **自回归采样（`generate_response`）**：基于“视觉 Token + 左填充 Prompt”逐步前向，做温度缩放与 Top-p（核采样），遇到 `eos_token_id` 后标记 `finished`，后续步输出 `pad_token_id` 并将 `next_step_mask` 置 `0`。
* **响应段对数概率求和（`compute_response_logprob_sum`）**：对移位后的 logits 计算 `log_softmax`，并通过 `positions >= (prompt_lengths - 1)` 掩码**仅累加回答部分的对数概率**（注意：这里传入的 `prompt_lengths` 实际是左填充后统一的 `prompt_ids.size(1)`）。
* **KL 惩罚与策略梯度更新（`train_multimodal_rl_policy`）**：
* 冻结 `ref_model`（SFT 副本）和 `rm`。
* 计算回答级别 KL 散度近似值 $\text{KL} = \log \pi_\theta(y|x,I) - \log \pi_{\text{ref}}(y|x,I)$（截断在 `[-20, 20]` 提升数值稳定性）。
* 塑形奖励 $R_{\text{shaped}} = R_{\text{RM}} - \beta \cdot \text{KL}$，在 batch 内做零均值、单位方差标准化得到 `advantage`，最后以 REINFORCE 形式更新策略：<img width="415" height="35" alt="90b0a367-c9a3-4540-ba1f-dd5621eca883" src="https://github.com/user-attachments/assets/c90de654-8beb-436c-96f7-93131e5168f1" />

## 三、 阶段对比与工程局限性

| 维度 | MM-SFT | MM-RM | MM-RL（当前实现） |
| --- | --- | --- | --- |
| **学习目标** | 模仿高质量多模态回答分布 | 学习图文上下文下的偏好排序打分 | 最大化带 KL 约束的奖励期望 |
| **关键损失函数** | 掩码后的 Causal LM 交叉熵 | Bradley-Terry `softplus(-(r_c - r_r))` | 标准化优势加权的策略梯度（REINFORCE） |
| **模型状态** | 全量可训练 | 独立打分头 + 编码器微调 | `policy_model` 训练；`ref_model`、`rm` 冻结 |
| **主要局限** | 难以直接惩罚“看似合理但胡编乱造”的偏好差异 | 依赖成对标注质量，样本少易过拟合 | 属于简化版 REINFORCE（无 Critic 基线、无 PPO clip ratio、每 epoch 仅采样一次） |

### 实际落地时的关键改进点

1. **视觉 Token 粒度**：当前只用 **1 个全局池化 Token** `[B, 1, H]`，空间细节与文字定位能力有限；实际 VLM 通常保留空间网格特征（如 `7×7 = 49` 个 patch tokens）或使用 ViT / Qwen-VL / SigLIP 等视觉编码器。
2. **RL 算法升级**：当前用的是 batch 级 REINFORCE 策略梯度；在更大批量或更长序列下，通常会引入 **PPO（Clipped Surrogate Objective + Value Critic）** 或 **GRPO** 提升训练稳定性。
3. **数据规模与分词细节**：示例仅有 2 条样本用于演示管线闭环，真实训练需扩充数据；此外 `MultimodalPreferenceDataset` 直接拼接 `prompt + chosen + eos_token`，若 `prompt` 末尾空格或特殊 Token 边界不一致，可能影响前缀对齐。
